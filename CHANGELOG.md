# История релизов TG Ledger

## 4.4.1 — готовый APK и автономный Create Key Premium

- Подписанный release APK с заранее согласованным публичным ключом; пользователь больше не обязан пересобирать проект.
- Автономный Windows EXE «Create Key Premium»: ввод ID/полного TGREQ1-запроса и числа дней, выдача и копирование кода. Не требует Python, Gradle, SDK или Android Studio.
- Новая отдельная пара создаётся вне исходников. Закрытый ключ выдаётся владельцу только в личном архиве; в GitHub/CI — лишь публичная конфигурация. Windows EXE не содержит встроенного общего private key.
- Native Windows smoke для Python GUI и самого frozen EXE; проверка выдачи без проекта; Android-проверка соответствия ключа BuildConfig, манифеста и репозитория.
- Сохраняются старые функции банков, API, push, Plus и интерфейса. `versionName=4.4.1`, `versionCode=20`.
- Прежняя APK-подпись не восстанавливается из activation .pem. Если есть конфликт подписи, нельзя удалять приложение для обхода без резервной копии; нужен прежний signing keystore. Release/debug могут установиться рядом, но данные не мигрируют автоматически.

## 4.4.0 — стабильные ключи и новая система выдачи активаций

- Windows-менеджер `START_ACTIVATION.cmd`: импорт прежнего ключа или явное создание нового, настройка проекта, проверка, выдача и копирование кода; сборка APK и установка по USB с проверкой ключа.
- Приватный ключ хранится вне папки версии: `%USERPROFILE%\.tg-ledger\activation\developer_private_key.pem`. Обновление проекта больше не требует копировать его между версиями. Импорт и создание никогда не заменяют уже существующий отличный ключ молча.
- Публичная настройка записывается автоматически в локальный `activation-public.properties`; она имеет приоритет над устаревшими Gradle-настройками. Из репозитория удалён пример общего публичного ключа.
- Публичный Key ID виден в приложении и инструменте. Запрос `TGREQ1` содержит установку, продукт и ожидаемый ключ; менеджер не выдаёт код с несовпадающим ключом.
- Формат `TG2` подписан RSA/SHA-256 и указывает Key ID; старые v1-коды продолжают проверяться тем же публичным ключом. Для старого APK есть выдача `--legacy-v1`.
- Отдельные причины отказа: отсутствующая настройка, другой ключ, повреждённая подпись/формат, другой телефон/продукт, дата в будущем, истёкший срок, ошибка безопасного сохранения.
- Ввод не стирается при отказе, повторное нажатие во время проверки блокируется. Коды с переносами из чата принимаются без изменения подписанного содержимого.
- Действующий более долгий/бессрочный доступ не сокращается при повторном вводе старого короткого кода. Проверка и запись защищены от гонки с восстановлением доступа при запуске.
- Добавлены регрессии Python CLI, реальные Windows GUI/clipboard smoke tests, межъязыковой Python→Kotlin тест подписи и Android Keystore-перезапуск.
- Банковские API, push, Plus-периоды, компактный интерфейс и прежние данные сохранены. `versionCode=19`, `versionName=4.4.0`, API User-Agent обновлён; схема Room/applicationId не менялись.

Новая пара ключей не может работать со старым APK без обновления публичного ключа. Менеджер делает настройку и сборку, но не обходит подпись установленного приложения и не заменяет подтверждение оплаты. Приватные ключи, платёжные токены и сертификаты APK не входят в исходный ZIP/GitHub.

## 4.3.3 — крупный релиз банковского импорта и адаптивного интерфейса

### API сохранено и расширено

- **monobank personal API не удалено**: токен, чтение счетов/выписки, периодическая синхронизация и запуск вручную.
- **ПриватБанк Автоклиент**: read-only выписка для бизнеса/ФОП, пагинация и идентификаторы проведённых операций. Это не API обычных розничных карт Приват24.
- Токены хранятся через Android Keystore; приложение не создаёт и не авторизует банковские платежи.
- Push, API и SMS остаются отдельными выбираемыми способами. Push — начальный выбор для новых установок, **не замена и не удаление API**.

### Банковские push без SMS и без токена

- Фоновый NotificationListenerService сохраняет однозначные операции без открытого экрана приложения.
- Разбор обычных, развёрнутых, InboxStyle и MessagingStyle уведомлений; несколько платежей не смешиваются в одну сумму.
- Повторное чтение банковских уведомлений, оставшихся в шторке, после подключения/переподключения и возвращения в push-режим.
- Точный повтор не создаёт вторую запись. Похожая отдельная покупка остаётся в очереди проверки, а не удаляется молча.
- OTP, отказы и сообщения только с балансом не создают расход.

### Plus и периоды

- В банках без Plus/активного trial — сегодня; с доступом — 7 дней, 30 дней и вся история.
- Проверка стоит перед запросом статистики. Потеря доступа возвращает окно к сегодняшнему дню.
- 30 дней — скользящий период, не начало календарного месяца. Сбор операций не прекращается из-за фильтра отображения.

### Компактный адаптивный интерфейс

- Баланс, доходы и расходы — одна карточка вместо нескольких больших блоков.
- На широком телефоне — три выровненных показателя; на узком экране/крупном шрифте — читаемая вертикальная структура.
- Помощник уменьшен, банковские настройки свёрнуты.
- Восстановление покупок — отдельная кнопка полной ширины.
- Название банка/категории и сумма перестраиваются по реально измеренной ширине текста; названия не сжимаются до фрагментов слова.

### Справка, системные файлы и проверка

- В справке приложения добавлен заметный блок «Що нового у 4.3.3» с перечислением крупных изменений и явным указанием, что API сохранено.
- Дописаны инструкции по банкам, разрешениям, фону, API и обновлению с сохранением ключей.
- `versionName=4.3.3`, `versionCode=18`; обновлён API User-Agent, README, документация, исходный сборник, дерево проекта и SHA-256 manifest.
- `applicationId`, схема Room и ключи пользователя не меняются из-за переименования релиза.
- CI: play/legacyV7 debug, play release с R8, unit, lint и реальные инструментальные тесты Android 8/16.
- Отдельное QA-приложение публикует настоящие Android push; оно не входит в APK TG Ledger. Нативные снимки и отчёты входят в исходный пакет.

### Честные границы

Android не отдаёт приложению историю уже удалённых уведомлений; после force-stop нужно открыть его снова. Универсального API всех банков не реализовано. API-тесты используют mock-серверы; настоящие счета и телефон пользователя в разработке не используются.
