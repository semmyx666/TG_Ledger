# TG Ledger 3.0 — автономный банковский импорт

## Структура

- `domain/.../bank/BankParser.kt`: независимый Kotlin-парсер, справочник банков, определение магазина/категории, денежных единиц и времени.
- `domain/.../bank/BankRepository.kt`: доменные модели и интерфейс хранения/аналитики без зависимостей от Android или Room.
- `data/.../local/Entities.kt`: канонические операции; сумма — Long в минимальных денежных единицах.
- `data/.../local/BankEntities.kt`: пользовательские категории, очередь подтверждения, SQL-агрегаты по источникам и категориям.
- `data/.../local/LedgerDatabase.kt`: явная миграция Room 1 → 2, без удаления базы.
- `data/.../repository/BankImportRepository.kt`: атомарное получение/подтверждение, защита от дублей, локальные переключатели и бюджет.
- `app/.../bank/BankNotificationListener.kt`: уведомления разрешённых банковских пакетов, пропуск групповых сводок.
- `app/.../bank/BankSmsReceiver.kt`: сбор частей новых SMS; защищённый системный broadcast, goAsync и ограниченное время обработки.
- `app/.../presentation/bank/BankViewModel.kt`: MVVM и реактивные фильтры дня, последних 7 дней, текущего месяца и всей истории.
- `app/.../presentation/bank/BankScreen.kt`: разрешения, статистика, категории, подтверждение, бюджет и CSV-экспорт.
- `app/.../presentation/editor/EntryScreen.kt`: наличные/карта, банк, встроенные и пользовательские категории; метаданные сохраняются при редактировании.

Полный текст всех исходников есть в SOURCE_CODE.md. PROJECT_TREE.txt содержит дерево, MANIFEST.sha256 — контрольные суммы.

## Настройка

После разблокировки открыть Банки (пятая вкладка) либо Настройки → локальный импорт. Прочитать согласие, включить импорт, открыть системный доступ к уведомлениям и разрешить TG Ledger. По умолчанию распознанные операции не попадают в баланс без подтверждения. Автоимпорт включается отдельно и работает только для однозначной суммы/направления с распознанным мерчантом, без признаков перевода и дубликата.

Play-variant не объявляет RECEIVE_SMS и SMS receiver. Для отдельной установки `legacyV7` содержит RECEIVE_SMS и кнопку запроса доступа. READ_SMS не нужен: старый SMS-ящик не читается. Android/инсталлятор может запретить restricted SMS permission; приложение не обходит эти ограничения. Legacy billing v7 не предназначен для текущей новой публикации в Play. Для Play используется variant с Billing v8.

## Примеры для локальных тестов

- `Оплата 1 200,50 грн у АТБ; картка *1234; 07.10.2026 22:59`
- `Оплата 100 грн у АТБ; баланс 900 грн` → сумма покупки 100, не 900.
- `Purchase 12.50 USD at Steam` / `Payment $12.50 at Steam`.
- `Зараховано 2000 грн` → доход, но без мерчанта требует подтверждения.
- `Переказ 100 грн` → подтверждение, не автоматическая трата.
- Только баланс, OTP, отклонённая операция → игнорирование.

Это тестовые примеры, не подтверждённые шаблоны всех версий банков. Фактический банк определяется по точному package уведомления либо allowlist SMS-отправителя, а не по рекламному тексту. Список включает Приват, Mono, Sense, A-Bank, Ощад, ПУМБ, Revolut, Wise, N26; package/sender-идентификаторы необходимо сверять с установленными версиями. Неизвестные отправители игнорируются. Текст разных банков и языков может не соответствовать шаблонам: для такого формата нужен отдельный адаптер и обезличенный тест. Нельзя гарантировать полноту банковской выписки через уведомления.

## Данные и точность

У entries добавлены sourceType, bankId, cardLast4, eventAtMillis, customCategoryId и origin. Старые строки получают UNKNOWN: программа не выдумывает, с какого счёта были потрачены прежние деньги. Если в сообщении нет даты/времени операции, хранится время получения с явной пометкой в очереди. Дата/время из сообщения поддерживают dd.MM.yyyy или dd/MM/yyyy с HH:mm[:ss]. Полный номер карты не сохраняется.

UAH/USD/EUR не смешиваются. Сумма парсится BigDecimal, без Double и без округления дробной части. Все итоги считаются SQL по полному набору данных, даже если экран показывает только 100 последних операций. Банковский раздел разделяет пользовательские категории; прежняя стандартная аналитика объединяет их в OTHER. Основной журнал предоставляет существующие поиск, редактирование и пагинацию.

Повтор одного eventKey игнорируется уникальным индексом. Похожие операции одного банка/валюты/суммы/направления в пределах 90 секунд при совпадении карты или магазина отправляются на проверку, а не удаляются: это может быть как SMS+push, так и две реальные покупки. Подтверждение и создание canonical entry выполняются в одной Room-транзакции. Внутренний перевод нужно игнорировать, иначе ручное подтверждение изменит доход/расход. Программа не знает автоматически, какие счета принадлежат одному человеку.

## Дополнительные функции

- очередь сомнительных операций и возможных дублей;
- исключение собственных переводов;
- категории с именем и HEX-цветом при создании;
- лимит текущего месяца отдельно для каждой валюты и индикатор его расходования, с отключением;
- редактирование импортированных операций в обычном редакторе;
- CSV всех сохранённых операций через системный выбор места, с защитой текстовых полей от spreadsheet-formula injection;
- очистка истории распознавания отдельно от финансовой базы;
- обновление календарного дня без частого опроса;
- самостоятельное отключение импорта и переход к отзыву разрешений.

CSV содержит минимальные денежные единицы и отдельную валюту/тип операции, а не неоднозначные денежные строки. Удаление базы не требуется. Для обновления использовать тот же applicationId/variant и прежний ключ подписи; не удалять приложение.

## Приватность и ограничения Android

Импорт не использует банковские API, ключи, сервер и HTTP. Полные тексты и OTP не сохраняются; очередь содержит только извлечённые поля и SHA-256 идентификатор события. Системные бэкапы отключены. Room хранится в приватном каталоге Android, но PIN — блокировка приложения, не шифрование базы. Поддержка rooted-устройств и forensic-защита не заявляются.

Экспорт пользователь выбирает сам: облачный DocumentProvider может синхронизировать экспортированный CSV. Курс валют, Play и системный SpeechRecognizer — отдельные прежние функции приложения, способные использовать сеть; для полностью локального банковского учёта они не требуются.

Доступ к уведомлениям включает системную возможность читать уведомления других приложений, хотя код обрабатывает только allowlist. Отказ от разрешения не блокирует ручной ввод. Android может скрывать текст/OTP, ограничивать сервис после force-stop, в рабочем профиле или из-за настроек производителя. Уже полученные до включения доступа сообщения не сканируются. Исторический полный импорт и гарантированная доставка недоступны без банковской выписки/API.

## Проверки и сборка

Запущены: ресурсный/структурный аудит, 10 проверок реальных SQL миграции/банковских агрегатов в SQLite, 12 JVM-проверок извлечённых RegEx, прежние SQL и голосовые RegEx. JUnit BankParserTest включён, но здесь не запускался.

Android SDK/Gradle dependency resolution/Kotlin compiler недоступны в sandbox. APK/AAB НЕ собран; KSP, реальные push/SMS, Room validation на Android, UI и восстановление разрешений на устройстве требуют проверки.

Локально: JDK 17 и Android SDK 36. Из корня:

```sh
./gradlew :domain:test :data:testPlayDebugUnitTest :app:testPlayDebugUnitTest
./gradlew :app:assemblePlayDebug
./gradlew :app:assembleLegacyV7Debug
```

Для приёмки: обновить поверх существующей версии, проверить UNKNOWN у старых строк, наличные/два банка, пользовательские категории, другую валюту, SMS+push дубль, реальную повторную покупку, перевод, OTP, недостаток разрешений, большие шрифты, выключение сервиса, экспорт и перезапуск. Сверить миграцию Room на физическом Android перед релизом.
