# Обновление с 3.3.2

1. Распакуйте 4.4.0 **в новую папку**. В архиве `gradlew`, `app`, `data` и `domain` лежат сразу в корне, без второй вложенной папки с тем же названием.
2. **Не создавайте новый ключ, если сохранился прежний.** Откройте `START_ACTIVATION.cmd` → «Импорт прежнего .pem» и выберите свой `developer_private_key.pem` в старой папке/резервной копии. Менеджер сохранит его вне папок версий и автоматически запишет публичный ключ в `activation-public.properties`. Ручной перенос base64 больше не нужен. Если ключ безвозвратно потерян, можно явно создать новый, но приложение нужно пересобрать с новым публичным ключом, а старые коды с ним несовместимы. Приватный ключ не отправлять в Git/GitHub/чат. Полная инструкция: `ACTIVATION_4.4.0_RU.md`.
3. Если используете собственный signing keystore, сохраните его и прежнюю конфигурацию подписи. Обновление APK поверх установленного приложения возможно только с тем же applicationId и ключом подписи. Обычный `playDebug` сохраняет прежний debug applicationId.
4. В Android Studio открывайте папку с `settings.gradle.kts`. Запускайте модуль **app**, вариант `playDebug`. `bank-fixture` — только тестовый отправитель уведомлений для CI, не основное приложение.
5. На телефоне: **Банки → Налаштування імпорту → Push банку (рекомендовано)**. Разрешите доступ к уведомлениям и фоновую работу в настройках батареи. SMS и банковский API-токен для push не нужны. Ранее явно выбранный SMS/API-режим сохраняется при обновлении, поэтому при необходимости переключите его один раз. **API не удалено:** для monobank или Автоклиента ПриватБанка бизнеса/ФОП выберите здесь «API банку»; в этом режиме вместо чтения push используются API-реквизиты соответствующего банка.
6. При разрешённом доступе повторное подключение читает сообщения банков, ещё оставшиеся в шторке. Уже удалённые push не доступны. После «Принудительно остановить» откройте приложение снова.
7. Первые 14 дней могут быть активным пробным периодом Plus. Поэтому длительные периоды в банках в это время доступны без оплаты. После его окончания, если Plus не активен, отображается только сегодняшний день.

Схема базы данных в 4.4.0 не менялась. При корректной установке обновления поверх приложения сохранённые операции остаются; удаление приложения или смена applicationId/signing key — другое действие и может привести к потере локальных данных. Не удаляйте приложение для обхода ошибки подписи без резервной копии данных.
