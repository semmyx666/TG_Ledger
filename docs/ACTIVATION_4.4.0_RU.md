# Активация 4.4.0 — без ручного переноса ключей и base64

## Быстрый путь в Windows

1. Распакуйте проект в новую папку. Запустите **START_ACTIVATION.cmd**. Нужен Python 3 с tkinter; стандартный установщик python.org включает его. Если нет cryptography, менеджер предложит установить её с вашего согласия.
2. **Если прежний ключ сохранился:** «Импорт прежнего .pem» → выберите найденный файл. Он копируется в `%USERPROFILE%\.tg-ledger\activation\developer_private_key.pem`, исходник не удаляется. Можно выбрать путь с пробелами и кириллицей. Это правильный путь для сохранения совместимости старых кодов.
3. **Если ключ безвозвратно потерян:** «Создать новый ключ» после предупреждения. Это локальная RSA-пара 3072 бит, не общий ключ из архива. Другая уже существующая стабильная пара не заменяется молча. Сразу сохраните резервную копию в защищённом месте. Подпись APK и ключ активации — разные ключи.
4. Менеджер автоматически создаёт локальный `activation-public.properties`. Не нужно вставлять длинную строку в PowerShell. Настройка имеет приоритет над старым значением в `~/.gradle/gradle.properties`.
5. «Собрать APK с этим ключом» или «Собрать и установить по USB». Нужны Android SDK/JDK/доступ к зависимостям; для USB — подключённый телефон с разрешённой отладкой. Сборка останавливается, если публичный ключ не настроен. Никаких удалений приложения или сброса данных.
6. В приложении: **Настройки → активация**. Сравните Key ID с менеджером. Нажмите **«Скопировать запрос активации»** и вставьте полный `TGREQ1|…` в менеджер. Укажите 5/30/другое число дней и «Выдать код». Запрос проверяет, что менеджер подписывает именно тем ключом, который ожидает установленное приложение.
7. «Скопировать только код» → вставьте в приложение → активировать. Срок начинается с выдачи, а не первого ввода. `0` дней — бессрочно. Оплату проверяет разработчик, не этот инструмент.

Код активации не универсален: он привязан к Installation ID, продукту и ключу. Приложение проверяет подпись полностью офлайн. Переносы строк из чата допускаются; поясняющий текст вокруг кода — нет.

## Что исправлено

- Ключ больше не привязан к `TG_Ledger-номер/tools/`. Для следующей версии достаточно открыть менеджер и нажать «Настроить проект» — стабильный ключ переиспользуется.
- Никакого общего примерного публичного ключа. Чистый исходник не заявляет работающую активацию без настройки; в приложении это явно объясняется.
- Key ID одинаково вычисляется Python и Android из SHA-256 DER публичного ключа (первые 16 hex-символов). Это идентификатор, не секрет и не сама проверка подписи.
- `TG2` содержит Key ID и подписанные поля. Проверка включает RSA/SHA-256, установку, продукт, дату и срок. Изменение кода не даёт доступ.
- Отказ имеет конкретную причину; введённый код не стирается до успешной проверки. Уже действующее более долгое право не сокращается старым коротким кодом.
- Приватный ключ не входит в APK, Git, ZIP и исходный сборник; публичная локальная настройка также игнорируется Git.

## CLI без окна

```powershell
python tools/issue_activation_code.py setup --import-key "D:\папка со старым проектом\tools\developer_private_key.pem"
python tools/issue_activation_code.py doctor
python tools/issue_activation_code.py issue --request "TGREQ1|A21C-FEA5-E432|KEY_ID_ИЗ_ПРИЛОЖЕНИЯ|ledger_plus" --days 5
```

В примере замените запрос полным значением из приложения: `KEY_ID_…` не является настоящим Key ID. Поддержана старая команда `issue --installation-id … --days 5`, но она не может сама проверить ключ **установленного** APK, поэтому предпочтителен `--request`. В stdout выводится только код; диагностика — в stderr.

Явное первое создание (не вместо существующего ключа):

```powershell
python tools/issue_activation_code.py setup --create-new
```

Сборка с обязательной конфигурацией:

```powershell
.\gradlew.bat -PREQUIRE_DEVELOPER_ACTIVATION=true :app:activationDoctor :app:assemblePlayDebug
```

Можно явно передать `--private-key` или `TG_LEDGER_PRIVATE_KEY`. Отдельное хранилище для намеренной миграции задаётся `TG_LEDGER_KEY_HOME`; обычному обновлению это не требуется. Никогда не удаляйте действующую пару ради устранения ошибки «ключи не совпадают».

## Совместимость и ограничения

- Старые v1-коды продолжают работать в 4.4.0 **с тем же публичным ключом**. Для старых APK выдавайте с `--legacy-v1`.
- Новый ключ не подойдёт старому APK: требуется пересборка/установка с соответствующим публичным ключом. Даже новый менеджер не может восстановить потерянный приватный ключ из публичного.
- Установка поверх приложения требует прежнюю подпись APK. При ошибке подписи не удаляйте приложение без резервной копии данных. Play-сборка и debug имеют разные applicationId/Installation ID.
- После переустановки Windows путь хранилища нужно восстановить из резервной копии; программно гарантировать сохранность единственного локального файла невозможно.
- Изменение даты/времени может сделать код «выданным в будущем» или истёкшим: включите автоматическую дату на обоих устройствах. Локальная офлайн-модель не заменяет серверную защиту от всех изменений системных часов.
- Менеджер сравнивает ключ проекта и подписанта; установленный APK подтверждается только его Key ID/запросом, не предположением «сборка была успешна».
