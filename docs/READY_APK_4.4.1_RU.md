# 4.4.1 — готовый APK и Create Key Premium

## Без исходного проекта и Android Studio

- Установите предоставленный **TG_Ledger-4.4.1.apk**. Это подписанная release-сборка для Android 8+ (`com.semmyx.ledger`, versionCode 20), не ZIP исходников.
- Распакуйте **полностью** личный архив Create Key Premium и запустите **Create Key Premium.exe**. Установленный Python, Gradle, SDK и Android Studio не нужны. Не запускайте EXE прямо внутри ZIP.
- В новом приложении откройте Настройки → Активация TG Plus → Скопировать запрос активации. В генератор можно вставить полный TGREQ1-запрос или короткий ID установки. Это не PIN и не уже выданный код.
- Укажите число дней (например 5 или 30; 0 — бессрочно), нажмите «Создать ключ Premium», затем «Скопировать код». Вставьте результат в приложение и активируйте.
- Срок начинается с выдачи кода. После подтверждения оплаты покупателю отправляется только его код, не личный генератор и не private-папка.

## Согласованная пара

APK уже содержит соответствующий публичный ключ. Личный генератор содержит отдельный private-файл для подписи; публичный EXE сам по себе его не содержит. Пользователю не нужно генерировать пару, переносить base64 или пересобирать приложение. Публичный Key ID и конфигурация сборки находятся в `delivery/activation-public.json`. Приватная пара и подпись APK хранятся отдельно от исходников/GitHub/CI.

Весь личный архив с private-папкой и резервной копией APK signing key — секрет разработчика. Не выкладывайте его на GitHub и не передавайте покупателям. Сохраните резервную копию в защищённом месте; будущие обновления должны использовать ту же подпись APK и тот же ключ активаций, если не проводится отдельная миграция.

## Важно при установке поверх старого приложения

Ключ активации и ключ подписи APK — разные вещи. Для обновления существующего пакета нужна прежняя подпись APK. Эта поставка использует новую отдельную подпись: если Android сообщает конфликт подписи, **не удаляйте старое приложение и не очищайте его данные**. Для совместимого обновления требуется прежний signing keystore (например старый debug.keystore), а не developer_private_key.pem.

Старая Android Studio debug-сборка имеет package `com.semmyx.ledger.debug`, новый release — `com.semmyx.ledger`: они могут установиться рядом, но локальные данные и разрешения не переносятся автоматически. ID установки берите именно из нового APK; у старой сборки он может отличаться. При изменении пары ключей старые коды не становятся действительными автоматически.

## Для сборки из исходников (покупателям не требуется)

`python tools/configure_delivery.py` использует только публичную конфигурацию. Затем `./gradlew -PREQUIRE_DEVELOPER_ACTIVATION=true :app:assemblePlayRelease`. CI собирает unsigned release APK; подпись производится отдельно вне CI, без раскрытия закрытых ключей. Windows EXE собирается PyInstaller и проверяется как настоящий frozen EXE с временным тестовым ключом, не с личным ключом владельца.
