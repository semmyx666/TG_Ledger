# TG Ledger 3.1 — запуск банков, История и диагностика импорта

## Падение из присланного лога

`No ActivityResultRegistryOwner was provided via LocalActivityResultRegistryOwner` возникало в BankScreen при создании SMS/CSV launchers. Локализация подменяет LocalContext на configuration Context, из которого Activity уже нельзя автоматически найти. Теперь AppRoot явно предоставляет настоящий host FragmentActivity как LocalActivityResultRegistryOwner и LocalOnBackPressedDispatcherOwner выше локализации и всех маршрутов. Разрешения/CSV больше не зависят от поиска Activity в локализованном Context.

Переходы в системные настройки также защищены: Context может быть не Activity, поэтому Intent использует FLAG_ACTIVITY_NEW_TASK, а ошибки открытия настроек перехватываются. Не используется случайный try/catch, который скрывает отсутствие registry; исправлен владелец.

## История

Кнопка История была ошибочно привязана к onBack, возвращавшему dashboard. Теперь есть отдельный history destination с месяцем, выбранным в аналитике, поиском, фильтром доход/расход, загрузкой следующих страниц и редактированием. Возврат из Истории идёт назад в аналитику. Это было неправильное действие навигации, а не доказанный системный crash.

## Что проверить для локального импорта

1. Банки → включить импорт. По умолчанию он выключен, а автоимпорт выключен отдельно.
2. Управление доступом к уведомлениям → разрешить TG Ledger. Вернуться и при необходимости нажать Переподключить.
3. Диагностика показывает подключение сервиса, количество уведомлений, банковских сообщений, последний package и причину обработки. Эти данные хранятся в памяти текущего процесса, не содержат текст уведомления. Package неизвестных приложений — только диагностическая метаинформация; их тексты не читаются.
4. Если уведомления есть, но банк не распознан: проверить идентификатор банковского приложения. Указать точный package для нужного банка. Не назначать мессенджеры и чужие приложения. Default allowlist сохранён.
5. Если формат не распознан: Вставить банковское сообщение → выбрать банк → вставить текст → проверить сумму/валюту/магазин → На подтверждение. Этот путь не требует listener/SMS доступа и работает даже при отключённой автоматике; сырой текст не сохраняется. Баланс меняется только после подтверждения записи в очереди.
6. Если программа сообщает Потребует подтверждения, это не отсутствие импорта. Очередь находится ниже на том же экране. До подтверждения операция намеренно не влияет на баланс.

Сервис показывает отдельные причины: отключено, неподдерживаемый package, пустой/скрытый текст Android, групповая сводка, неподдерживаемый формат, очередь, возможный дубль, автоматическое сохранение, повторная доставка и ошибка хранения. На отключении listener запрашивается системное переподключение; имеется ручная кнопка.

Парсер получил ограниченный fallback для названия магазина в заголовке/отдельной строке. Автоматическая запись с fallback требует узнаваемой категории; неизвестный магазин остаётся на подтверждение. OTP/отклонённые операции/только баланс по-прежнему игнорируются. Банковские приложения меняют форматы; без реального обезличенного сообщения невозможно доказать, что конкретный неизвестный шаблон теперь поддержан.

SMS, как раньше, доступны только в legacyV7 sideload manifest. Play variant не содержит SMS-разрешений. Нет доступа к историческому SMS-ящику или старой истории уведомлений. Скрытые Android тексты и отсутствующие уведомления невозможно восстановить парсером. Банковский API не добавлен.

## Проверки

Выполнены: структурный ресурсный аудит, реальные SQL миграции/банковских агрегатов в SQLite, реальные исходные RegEx на JVM, прежние SQL/voice проверки и source regression guards для owners/history/manual recovery. Проверки исходного текста не являются Android UI-тестами.

Android-сборка была действительно запущена, но завершилась до компиляции: curl exit 6, Could not resolve host: raw.githubusercontent.com при загрузке официального Gradle wrapper. Лог: verification/android-build-3.1.log. APK не собран, Kotlin/KSP и тест на физическом телефоне не выполнены. Не заявляется гарантия отсутствия всех ошибок.

Приёмка на телефоне: запуск и PIN → Банки; SMS-запрос; CSV chooser с подтверждением и отменой; доступ к уведомлениям; переподключение; новое уведомление; очереди и дубли; manual paste; аналитика → История → редактирование → возврат; EN/UK; большие шрифты; холодный запуск. Использовать тот же variant, applicationId и прежний ключ подписи, без удаления приложения — финансовая база и подписка должны сохраниться.
